**A01 — P1: Isolate editor history between runs**

Source: [RichSection reset](</Users/louishess/Documents/ChatGPT/Custom ELB/src/components.tsx:185>), [editor update callback](</Users/louishess/Documents/ChatGPT/Custom ELB/src/components.tsx:165>), [run-change handling](</Users/louishess/Documents/ChatGPT/Custom ELB/src/App.tsx:89>).

The same Tiptap editor instance is reused when changing runs. Calling `setContent(document, { emitUpdate: false })` replaces its document without isolating its Undo history. Suppressing the update event does not clear that history.

Reproduction: create runs A and B with different Information text; edit A to `RUN A EDITED`, wait for Saved, select B, and click Undo. B first displays `RUN B ORIGINAL`, then displays `RUN A EDITED`. Navigating away flushes autosave, and reading the database confirms that **B now stores A's edited content**. No filesystem fault or direct editor-state manipulation was used.

Next agent: recreate or explicitly reset the editor state/history when record identity or library generation changes. Preserve ordinary Undo within one run. Regression acceptance must cover Undo and Redo after A→B, all four sections, and authoritative reload/restore of a record with the same ID. Verify persisted content, not only visible text. Evidence: `ui-probes.log`, probe `undo-across-entries`.

**A02 — P1: Separate restore commitment from obsolete-file cleanup**

Source: [restore cleanup and catch path](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/backup.cjs:1079>), [destructive rollback](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/backup.cjs:1109>).

After reopening the candidate library, `switchLibrary` removes the old swap database and then the old swap objects. If the latter removal fails, its catch block deletes the live candidate database and tries to rename the already-deleted old database back. The retained rollback copy is only used in the `else` branch when `currentDbMoved` is false, so it does not rescue this case.

Reproduction: inject one `EIO` only while removing `content/swap/objects`, after the old database has been removed. Restore returns `IO`, leaves `preserveStaging: true`, and **the live database no longer exists**. Calling the actual `recoverRestoreJournal` then fails with “The interrupted restore could not be recovered.” A retained rollback directory still exists: this is an application recovery failure, not demonstrated permanent loss of every copy.

Next agent: establish a durable commit boundary and treat post-commit cleanup failures as cleanup failures. If rollback is necessary, select a complete recoverable database/object pair before deleting live data. Add fault tests for each cleanup and journal operation after candidate reopen, including recovery on a fresh startup. Evidence: `backup-probes.log`, `cleanup-error-after-open`.

**A03 — P1: Do not report cancellation after a committed restore**

Source: [worker post-operation abort check](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/worker.cjs:529>), [restore commit](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/backup.cjs:1078>), [renderer success-only replacement](</Users/louishess/Documents/ChatGPT/Custom ELB/src/panels.tsx:173>).

The worker unconditionally checks its abort signal after the service returns. A cancellation accepted during final restore cleanup can therefore turn a completed database replacement into a `CANCELLED` response. The renderer only calls `onRestored` on success and otherwise retains the old snapshot while saying restore was cancelled.

Reproduction: use the real worker runtime and backup service; dispatch `jobs.cancel` from the restore service's `committed` phase hook. The worker returns `{ok:false,error:{code:'CANCELLED'}}`, while the store contains `BACKUP STATE` instead of `CURRENT STATE`. The commit hook makes the narrow timing window deterministic. Renderer divergence follows directly from the success-only handler; this particular cancellation race was tested at the worker/service boundary.

Next agent: model non-cancellable commitment explicitly. Once replacement occurs, return an authoritative result that triggers renderer/library-generation replacement. Test cancellation before switching, during switching, and after commitment through the main/worker/renderer chain. Evidence: `backup-probes.log`, `cancel-after-commit`.

**A04 — P1: Protect unrelated Markdown companion-directory contents**

Source: [companion target selection](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/exports.cjs:1413>), [replacement and backup deletion](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/exports.cjs:1440>), [primary-file confirmation](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/main.cjs:1097>).

Markdown export treats the entire generated `<stem>_assets` directory as replaceable. Main-process confirmation only checks the primary selected file. No ownership check establishes that an existing sibling directory belongs to this export.

Reproduction: create `report_assets/unrelated-research.txt`, leave `report.md` nonexistent, then export Markdown with an image preview to `report.md`. Export succeeds, **the unrelated sentinel disappears**, and the asset directory contains only the generated image. This does not depend on agreeing to replace an existing primary file.

Next agent: allocate a unique asset directory or track which files LabMate owns. Preserve unowned contents; any whole-directory replacement needs an explicit decision covering that directory. Regression acceptance should include unrelated files, another export's assets, repeated exports, and failure while promoting the output set. Also inspect the adjacent rollback path: failed rename-back errors are swallowed before backup-directory cleanup; that additional failure path was source-reviewed but not separately fault-tested. Evidence: `export-probes.log`, `markdown-companion-overwrite`.

**A05 — P2: Make whole-notebook export requests match the contract**

Source: [ExportPanel request construction](</Users/louishess/Documents/ChatGPT/Custom ELB/src/panels.tsx:426>), [backend scope validation](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/exports.cjs:234>).

`ExportPanel` always sends `visibleOrder.map(run => run.id)` as `runIds`. The backend requires notebook-scope requests to have an empty `runIds` list. Every nonempty whole-notebook selection therefore fails before rendering.

Reproduction: open a populated notebook, choose Export notebook, select TXT, and submit. The UI reports `Notebook export does not accept runIds`; the destination file does not exist. The mismatch precedes format rendering and therefore also affects the other offered formats.

Next agent: build scope-specific requests and retain backend validation. Test the real UI for entry, selected, and notebook scopes across formats, including scheme order. Fix A08 alongside this issue so restoring this UI path does not expose hidden trashed records. Evidence: `ui-probes.log`, `whole-notebook-export`.

**A06 — P2: Share export ordering values across UI and backend**

Source: [offered sorting values](</Users/louishess/Documents/ChatGPT/Custom ELB/src/fixtures.ts:23>), [export request](</Users/louishess/Documents/ChatGPT/Custom ELB/src/panels.tsx:431>), [backend order enum](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/exports.cjs:36>).

The UI sends `title-az`, `title-za`, `label-az`, and `author-az`. The backend instead accepts legacy `az`/`za` and has no label/author order values. Reproduction through the selected-entry export UI returns `Unsupported export order: title-az`. The other three values are rejected by the same explicit membership check.

Next agent: use a shared typed ordering contract, normalize any legacy aliases deliberately, and implement the label/author comparators with stable ties. Test every option actually offered in the export UI; backend-only tests using its older enum miss this regression. Evidence: `ui-probes.log`, `title-order-export`.

**A07 — P2: Only block Trash restore when an ancestor is actually trashed**

Source: [experiment Trash mapping](</Users/louishess/Documents/ChatGPT/Custom ELB/src/workflows.ts:92>), [disabled restore control](</Users/louishess/Documents/ChatGPT/Custom ELB/src/panels.tsx:246>).

`activeTrash` always sets a trashed experiment's `ancestorId` to its notebook ID, even when that notebook is active. The UI interprets any `ancestorId` as a blocking trashed parent.

Reproduction: trash an experiment while leaving its notebook active, then open Settings → Trash. The row falsely says it is inside a trashed notebook, directs the user to restore that notebook first, and disables Restore. That notebook has no Trash row to restore.

Next agent: assign blocking ancestry only when the ancestor is trashed, consistent with the existing run branch. Test experiments under active notebooks, experiments under trashed notebooks, and restoring the parent before the child. Evidence: `ui-probes.log`, `restore-trashed-experiment`.

**A08 — P2: Exclude runs whose experiment is trashed from exports**

Source: [backend active-run filter](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/exports.cjs:510>), [parent existence-only check](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/exports.cjs:546>), [renderer ancestor-aware visibility](</Users/louishess/Documents/ChatGPT/Custom ELB/src/workflows.ts:27>).

The export resolver checks the run's own `trashedAt`, but not its experiment's. Trashing an experiment does not require setting each descendant run's own trash flag. Snapshots intentionally retain trashed records, so export must apply ancestor visibility itself.

Reproduction: create an active experiment/run and another experiment/run; trash only the latter experiment; call notebook export selection with the contract-valid `runIds: []`. The resolved entries contain both `ACTIVE RUN` and `HIDDEN TRASHED EXPERIMENT RUN`. A05 currently blocks the ordinary notebook-export UI before reaching this defect; this finding is backend-reproduced, not a claim that today's broken UI routinely exports those records.

Next agent: centralize ancestor-aware selection and apply it to notebook, explicit selected/entry, and scheme exports. Reject explicitly requested inactive descendants. Evidence: `export-probes.log`, `export-trashed-experiment`.

**A09 — P2: Permit recovery from a damaged current attachment set**

Source: [current-library rollback validation](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/backup.cjs:846>), [restore sequence](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/backup.cjs:1282>).

Before installing an independently validated incoming backup, `currentLibraryForRollback` requires every current attachment object to exist and pass hash/size validation. A broken current attachment therefore prevents the operation intended to recover it.

Reproduction: create a valid encrypted backup containing an attachment, update the current run, delete only the current library's attachment object, and restore the valid backup. Restore returns `IO` / `Restoring the encrypted backup failed.`, leaves the current run in place, and does not restore the missing attachment. The incoming archive is intact.

Next agent: preserve the damaged current state as found while validating the candidate independently. Provide a recovery path that does not require a healthy current snapshot; retain available current files for review. Do not weaken incoming archive validation. Test missing and corrupt current objects separately from corrupt incoming archives. Evidence: `backup-probes.log`, `restore-missing-current-attachment`.

**A10 — P2: Include caption drafts in the close-save lifecycle**

Source: [caption state and save](</Users/louishess/Documents/ChatGPT/Custom ELB/src/panels.tsx:377>), [blur-only trigger](</Users/louishess/Documents/ChatGPT/Custom ELB/src/panels.tsx:401>), [window-close flush](</Users/louishess/Documents/ChatGPT/Custom ELB/src/App.tsx:102>).

Attachment captions live in panel state and save only on textarea blur. The application close handshake flushes section documents but does not flush that caption state.

Reproduction: open an attachment, type `UNSAVED CAPTION AT WINDOW CLOSE`, leave focus in the caption, and close the real BrowserWindow through its normal `close()` lifecycle. Reopening the disposable database shows an empty caption. This was not a force-kill test.

Next agent: register caption drafts with a close/navigation flush or implement an explicit durable save lifecycle. A failed caption save must retain the draft and block or clearly resolve closure. Test ordinary close/quit without blur, panel dismissal, and save failure. Evidence: `ui-probes.log`, `caption-at-window-close`.

**A11 — P2: Make Retry reinitialize failed backend services**

Source: [cached initialization failure](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/worker.cjs:477>), [worker reuse](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/main.cjs:625>), [renderer retry load](</Users/louishess/Documents/ChatGPT/Custom ELB/src/App.tsx:49>).

`ensureServices` stores the first initialization error and throws it forever. The worker process remains alive, so main-process `start()` reuses it. Retry asks that same worker for another snapshot without clearing or retrying initialization.

Reproduction: obstruct the disposable library's objects directory with a regular file, request a snapshot, remove the obstruction, and request again. Both responses are `UNAVAILABLE`. A new worker against the repaired directory succeeds.

Next agent: make the explicit recovery action restart or safely reinitialize services, retain a useful underlying failure reason, and avoid automatically replaying mutations. Test a resolved transient startup failure as well as an unresolved one. Evidence: `worker-retry-probe.log`.

**A12 — P2: Reduce full-library work on routine mutations**

Source: [all-mutation snapshot return](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/store.cjs:673>), [per-run document query and validation](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/store.cjs:761>), [whole-library assembly](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/store.cjs:783>), [appearance writes](</Users/louishess/Documents/ChatGPT/Custom ELB/src/App.tsx:313>).

Every mutation rebuilds the full snapshot, including all runs' four rich-text documents and trashed content. Each run adds a prepared query, JSON parsing, and document validation. The complete result then goes through worker/renderer transport. Even dragging the appearance slider issues preference writes at each change. This behavior follows the existing full-snapshot contract, but its scaling cost is measurable.

Synthetic benchmark on the audit host: one experiment/run per item, all four sections containing 2,135 ASCII text characters, one warmup snapshot and three measured reads. Times below measure synchronous store work; transport and React rendering are excluded. Payload size is its JSON representation, not a measurement of IPC wire encoding.

| ---: | --- | ---: | ---: | ---: |
| 100 | 3.6 / 3.2 / 3.0 | 3.1 | 956,696 | 0.7 |
| 1,000 | 30.3 / 28.7 / 29.0 | 29.8 | 9,565,199 | 6.4 |
| 5,000 | 148.9 / 160.5 / 147.0 | 147.2 | 47,837,199 | 31.7 |

Next agent: coordinate a shared-contract change for incremental mutation results and loading documents on demand; first consider coalescing preference writes and eliminating per-run queries. Preserve library-generation replacement and stale-revision protection. Measure startup, typing/autosave, slider interaction, and memory on growing libraries; these numbers alone do not establish end-to-end UI latency. Evidence: `performance-probes.log` and its reproducible seed script.

**A14 — P3: Finish the global preview progress lifecycle**

Source: [preview progress and return paths](</Users/louishess/Documents/ChatGPT/Custom ELB/electron/backend/files.cjs:623>), [global progress clearing](</Users/louishess/Documents/ChatGPT/Custom ELB/src/App.tsx:72>), [local preview completion](</Users/louishess/Documents/ChatGPT/Custom ELB/src/AttachmentPreview.tsx:224>).
